# 管理画面 新アーキ移行 棚卸し（旧 admin → apps/admin）

作成: 2026-07-23 / **最終更新: 2026-08-01** / 対象ブランチ基準: `ota/develop`

## 目的
旧 `admin/`（Next.js / Supabase Auth / service_role）から、新アーキ管理フロント
`apps/admin`（Vite + TanStack Router/Query SPA / Cloudflare Access / app_admin 経由の
Hono RPC）への移行状況を棚卸しし、**完全カットオーバーまでの残作業**と優先順位を示す。

新アーキの原則は [docs/TARGET_ARCHITECTURE.md](TARGET_ARCHITECTURE.md)（Phase 4）。
旧 admin は**カットオーバーまで並行稼働**（ビッグバン書き換え禁止）。

カットオーバーの具体手順は [20260801_0758_admin カットオーバー準備.md](20260801_0758_adminカットオーバー準備.md) を参照。

## 2. 未移行（要判断・インフラ前提）

残りはいずれも**技術／運用の意思決定が先**に必要なもの。

| 機能 | 旧 feature | 判断ポイント | 優先度 |
|---|---|---|---|
| 議案サムネイル画像 | `bills-edit` の `thumbnail-upload` / `thumbnail-storage` | 画像の置き場（**R2 バケット**）・公開 URL 設計・アップロード経路（api 経由の署名 URL 等）を決める必要がある | 中 |
| 管理者管理 | `admins` (476) | **Cloudflare Access の認可設計とセット**。Access のユーザー/グループ管理で代替するのか、アプリ側にも管理者テーブルを持つのかの設計判断が先 | 低〜要判断 |
| 速報版（sokuhou）からの取込 | `ai-collection` の `import-from-sokuhou` | 定例会ページ取込（#142）で実運用が回るかを見てから判断 | 低 |

## 3. 移行不要（廃止・置換・不要化）

| 機能 | 旧 feature（LOC） | 判断 |
|---|---|---|
| トピック分析 | topic-analysis (3354) | 🚫 **廃止**。旧 topic_analysis は非公開レポート混入の privacy 問題があり、新設計は事前同意＋public_reader 経由の集約（apps/web の opinions-summary）に置換済み |
| インタビューシミュレーション | interview-simulation (6010) | 🚫 dev/評価ツール。後継は `apps/api/src/eval/`（eval harness）。管理機能としての移行は不要 |
| 認証 | auth (369) | 🚫 **Cloudflare Access**（Zero Trust + Google IdP）に置換。自前ログイン/セッションは移行しない |
| インタビュー質問の事前作成 | interview-config の質問エディタ | 🚫 **不要**。新エンジンは対象ごとに設定をオンデマンド自動作成し、質問は loop で動的生成する（`interview_questions` 不使用） |
| AI 収集の実行履歴（runs） | ai-collection の `storage.ts` / `run-history` | 🚫 **不要**。旧実装はローカルファイルにドラフトを保存していたが、Workers ではファイルシステムを持てないため、抽出→レビュー→取り込みの**ステートレス2段**に置き換え（#141）、履歴という概念自体が不要になった |
| MCP ツール | mcp (530) | 要判断（内部向け。新アーキで必要かは別途） |

## 4. カットオーバー条件（旧 admin 停止の目安）

1. ✅ 主要運用機能の移行完了（§1 のとおり。#142 のマージで議案系も完了）
2. ⬜ §2 の未移行機能について「移行する／Access 等で代替する／当面は旧 admin を残す」を**明示的に決める**
3. ⬜ **apps/admin のデプロイ経路を用意**（現状 `apps/admin` に wrangler 設定なし＝未デプロイ）
4. ⬜ **本番 Cloudflare Access アプリの構築**＋api への `CF_ACCESS_TEAM_DOMAIN` / `CF_ACCESS_AUD` 設定
5. ⬜ 新 admin での**受け入れ確認**（実データでの一通りの運用）
6. ⬜ 旧 admin（Cloud Run）の停止・DNS/リンクの切り替え

→ 手順の詳細は [カットオーバー準備](20260801_0758_adminカットオーバー準備.md)。

## 5. 補足
- 旧 admin の LOC は移行前の実測（テスト含む）。新アーキでは API 化＋SPA 化で総量が圧縮される傾向にある（例: 議案系の複数 feature が `apps/api/src/routes/admin/bills*.ts` ＋ `apps/admin/src/features/bills*/` に集約）。
- 一括取り込み（#142）では旧実装の純粋関数（HTML パーサ・マッピング・本文組み立て）を**テスト57件ごと** `packages/shared/src/bills-import/` へ移植した。パーサは正規表現のみで外部ライブラリ非依存のため Workers でもそのまま動作する。
