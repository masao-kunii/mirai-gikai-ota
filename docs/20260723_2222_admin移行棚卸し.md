# 管理画面 新アーキ移行 棚卸し（旧 admin → apps/admin）

作成: 2026-07-23 / 対象ブランチ基準: `ota/develop`

## 目的
旧 `admin/`（Next.js / Supabase Auth / service_role）から、新アーキ管理フロント
`apps/admin`（Vite + TanStack Router/Query SPA / Cloudflare Access / app_admin 経由の
Hono RPC）への移行状況を棚卸しし、**完全カットオーバーまでの残作業**と優先順位を示す。

新アーキの原則は [docs/TARGET_ARCHITECTURE.md](TARGET_ARCHITECTURE.md)（Phase 4）。
旧 admin は**カットオーバーまで並行稼働**（ビッグバン書き換え禁止）。

## 凡例

- 🟡 進行中（オープン PR）
- ⬜ 未移行
- 🚫 移行不要（廃止／別置換／インフラで対応）

## 4. カットオーバー条件（旧 admin 廃止の目安）

以下がすべて「移行済み or 移行不要と確定」になった時点で旧 `admin/` を停止できる:

1. §2 の **高優先（インタビュー設定・議事録）** の移行完了
2. §2 の議案系残り（サムネ・マージ・インポート）と専門家・通報一覧の移行完了
3. §2 の管理者管理を Cloudflare Access ベースで再設計・移行（または「Access のユーザー/グループ管理で代替」と確定）
4. §3 の廃止・置換対象（topic-analysis / interview-simulation / auth）を「移行しない」と正式確定
5. 本番 Cloudflare Access アプリの構築＋api への `CF_ACCESS_TEAM_DOMAIN`/`CF_ACCESS_AUD` 設定（インフラ作業）

## 5. 推奨着手順序（案）

1. **インタビュー設定（interview-config）** — 審査キューと対で、インタビュー運用の中核。これが移ると「インタビューの作成〜公開〜審査」が新 admin で一巡する
2. **議事録（minutes）** — 会期に紐づく独立ドメイン。中規模で移しやすい
3. 議案の残り（**サムネ → マージ → インポート**）と **専門家**・**通報一覧**
4. **管理者管理**は Access の認可設計とセットで最後に整理
5. 並行して本番 Access のインフラ準備

## 6. 補足
- LOC は旧 admin の `.ts/.tsx` 実測（テスト含む）。新アーキでは API 化＋SPA 化で総量は圧縮される傾向（例: 議案系は複数旧 feature が `apps/api/src/routes/admin/bills.ts` + `apps/admin/src/features/bills/*` に集約済み）。
- 数字はあくまで規模感の目安。実移行時は依存（bill/theme/faction/committee 参照）と RLS・公開境界（app_admin / public_reader）の整合を都度確認する。
