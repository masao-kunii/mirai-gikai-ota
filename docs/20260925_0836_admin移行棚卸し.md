# 管理画面 新アーキ移行 棚卸し（旧 admin → apps/admin）

作成: 2026-09-25 / 対象: `ota/develop` (#173 マージ時点)
前版: [20260723_2222_admin移行棚卸し.md](20260723_2222_admin移行棚卸し.md)

## この版での変化
前版（2026-08-01）以降に、旧 admin を止めるのに必要な機能の移行が完了した。

- 議事録 PDF からの本文抽出（#167）
- インタビュー回答の閲覧（一覧・統計・会話ログ・公開切替）（#169）
- インタビューレポートの一括公開と再判定（#173）

あわせて、前版の「未移行」欄が実態より少なかった点を修正した。前版は3件しか挙げていなかったが、旧 admin のページ26件・Server Action 48件を機械的に突き合わせた結果、下記 §3 のとおり6件が残っている。

## 凡例
- ✅ 移行済み（`ota/develop` にマージ済み）
- ⬜ 未移行
- 🚫 移行不要（廃止／別置換／インフラで対応）

### 議事録

| 機能 | 新 admin の画面 | PR |
|---|---|---|
| CRUD・本文の手動編集 | `/minutes`, `/minute-edit/:id` | #136 |
| **PDF からの本文抽出（1件／未抽出の一括）** | `/minutes` | #167 |

抽出方式は旧 admin から変えた。旧は Gemini に PDF を渡して書き起こしていたが、61ページで数分かかり出力上限で切れるおそれもあるため、pdf.js（unpdf）で PDF の文字をそのまま抜く。解析はブラウザで行い、api は元 PDF の中継（`GET /minutes/:id/source-pdf`）と抽出結果の保存（`PUT /minutes/:id/extracted-text`）だけを持つ。Workers の CPU 時間に PDF 解析を載せないため。

### インタビュー

| 機能 | 新 admin の画面 | PR |
|---|---|---|
| インタビュー設定（受付/終了の切替・基本編集） | `/interview-configs` | #126 |
| 審査キュー（承認/却下） | `/review-queue` | #124 |
| 通報（レポート単位の集約・非公開化） | `/report-flags` | #138 |
| **回答の一覧・絞り込み・並べ替え・統計** | `/interview-sessions` | #169 |
| **会話ログとレポートの詳細・公開切替** | `/interview-session/:id` | #169 |
| **条件を決めた一括公開** | `/interview-sessions` | #173 |
| **モデレーション・内容充実度の再判定（1件／未評価の一括）** | `/interview-sessions`, 詳細 | #173 |

旧 admin は議案ごとの画面だったが、新エンジンの対象は議案・区政テーマ・取り組みに広がったため、インタビュー設定で絞り込む1つの画面にまとめた。

## 2. 移行不要

| 機能 | 旧 feature | 判断 |
|---|---|---|
| 管理者管理 | admins | 🚫 Cloudflare Access のポリシーが唯一の管理者定義（2026-08-01 決定） |
| 認証 | auth | 🚫 Cloudflare Access に置換 |
| トピック分析 | topic-analysis | 🚫 廃止。非公開レポート混入の privacy 問題があり、事前同意＋public_reader 経由の集約に置換済み |
| インタビューシミュレーション | interview-simulation | 🚫 dev/評価ツール。後継は `apps/api/src/eval/` |
| インタビュー質問の事前作成 | interview-config の質問エディタ | 🚫 新エンジンは質問を対話中に動的生成する |
| AI 収集の実行履歴（runs） | ai-collection の storage | 🚫 Workers にファイルシステムが無いため、抽出→レビュー→取り込みのステートレス2段に再設計（#141） |

## 3. 未移行

旧 admin を止めるのに必須ではないが、運用の利便性として残っているもの。

| 機能 | 旧の実装 | 補足 |
|---|---|---|
| 議案のプレビュー URL 発行 | `bills/generate-preview-url`、`interview-config/generate-interview-preview-url` | 下書き議案を公開前に確認する導線。トークン発行の仕組みごと未移行 |
| 議案の一括更新 | `bills/bulk-update-bills` | 公開状態・注目フラグをまとめて変更し、`published_at` を揃える |
| 議案の複製 | `bills/duplicate-bill` | |
| 議案一覧の絞り込み・並べ替え | `bills` の sort/filter パラメータ | 新 `GET /admin/bills` はクエリ条件を持たず全件返す。件数が増えると重くなる |
| 会派見解の再取り込み | `ai-collection/reapply-stances` | 一括取り込み（#142）で代替できるかは要判断 |
| 速報版からの議事録取込 | `minutes/import-from-sokuhou` | 定例会ページの一括取り込みで運用が回るかを見てから判断 |

## 4. カットオーバー（旧 admin 停止）の残手順

1. ✅ 運用機能の移行（§1）
2. ✅ `apps/admin` のデプロイ経路（`wrangler.jsonc`・#143）と Terraform 定義（#147）
3. ⬜ **Terraform apply**：`admin_enabled` / `admin_hostname` / 許可メール（`infra/terraform.tfvars`）
4. ⬜ **api に `CF_ACCESS_AUD` と `CF_ACCESS_TEAM_DOMAIN` を設定**（現在は未設定のため `/api/admin/*` は 500 で閉じている＝fail-closed）
5. ⬜ `apps/admin` のデプロイ
6. ⬜ 実データでの受け入れ確認
7. ⬜ 旧 admin（Cloud Run）の停止

手順の詳細は [20260801_0758_adminカットオーバー準備.md](20260801_0758_adminカットオーバー準備.md)、デプロイ自体は `.claude/skills/deploy/` を参照。

## 5. 補足
- 本番へのデプロイは手動（GitHub Actions にデプロイジョブは無い）。マージしただけでは反映されない
- 管理画面のモデルは `gemini-3.8-flash`（#168）。Developer API では `gemini-2.5-pro` が使えないため切り替えた
