# デプロイ手順と CI/CD（みらい議会＠大田区）

最終更新: 2026-06-24

## 前提

- 本番は **Cloud Run**（`asia-northeast1`、プロジェクト `mirai-gikai-ota`）。フロントに **Cloudflare**（web の CDN/WAF）。
- 公開 web: https://ota.aix.tokyo （Cloud Run ドメインマッピング）
- admin: Cloud Run 直 + IAP
- DB は **Supabase Cloud**。マイグレーションは別途 `supabase db push`（実行者: 管理者）。

## CI（GitHub Actions）

`ota/develop` への push / PR で以下が自動実行される（トリガーに `ota/develop` を追加済み）。

| ワークフロー | 内容 |
|---|---|
| `code_check.yml` | `pnpm lint` / `typecheck` / `build` / `test:coverage`（Node 22） |
| `integration_test.yml` | CI 内でローカル Supabase を起動し DB function 統合テスト（Node 22） |
| `pinact_check.yml` | ワークフローの third-party action が SHA ピン留めか検証 |
| `sync_teirei.yml` | 毎日10時 JST に大田区議会サイトから議案・会派見解を本番へ自動同期 |

- **Node バージョンは 22**（`.nvmrc` で固定）。Node 18 では jsdom@28 が `ERR_REQUIRE_ESM` で落ちるため、ローカルでも `nvm use`（=22）で開発すること。
- Codecov 送信は `CODECOV_TOKEN` 未設定でも CI を落とさない（`continue-on-error`）。

## CD（本番デプロイ）= 手動

> 自動デプロイは無い（旧 `deploy.yml` は upstream の Vercel 用で実態と不一致のため削除済み）。
> マージ後、本番に反映するには以下を手動実行する。

### 1. 認証（必要時）

```bash
gcloud auth login                      # gcloud 操作用
gcloud auth application-default login   # ADC（enrich 等のローカル AI 実行用）
gcloud config set project mirai-gikai-ota
```

### 2. デプロイ対象を最新化

```bash
git checkout ota/develop && git pull
```

### 3. Cloud Run へデプロイ（web / admin）

```bash
# web（公開サイト）
gcloud builds submit --config cloudbuild.web.yaml --project mirai-gikai-ota .

# admin（管理画面）
gcloud builds submit --config cloudbuild.admin.yaml --project mirai-gikai-ota .
```

- `cloudbuild.*.yaml` に substitution（リージョン/サービス名/GA_ID 等）と Secret Manager 参照が定義済み。追加引数は不要。
- web と admin は独立した Cloud Build。並行実行も可。各 3〜5 分程度。

### 4. DB マイグレーションがある場合のみ

```bash
supabase db push --include-all   # 本番DBへ適用（実行者: 管理者）
```

### 5. デプロイ後の確認

```bash
# リビジョン確認
gcloud run services list --region asia-northeast1 --project mirai-gikai-ota

# 公開サイトのスモーク（後述の E2E スモークも利用可）
curl -s -o /dev/null -w "%{http_code}\n" https://ota.aix.tokyo/
```

## メモ

- GitHub Secrets は現状 `SUPABASE_URL` / `SUPABASE_SECRET_KEY`（`sync_teirei` 用）のみ。
- CI から Cloud Run への自動デプロイ（Workload Identity Federation 等）は将来の課題。現状は手動デプロイで運用する。
